# 经济待办（统一定价之后遗留）

统一定价（价格簿 + `server/pricing.py`）堵住了「买入价低于回收价」和「加工链超额增值」两类问题。
下面这些是**这次明确没动**的，数据是改版时量到的现状。

## 1. 灶台日收入失衡

| 项 | 现状 |
| --- | --- |
| 自由组合（灶台 brew） | 每天 24 次，混搭菜均价约 108 票，满打满算约 2.6k 票/日 |
| 定点菜 | 每天 10 次 |
| 种地（对照） | 约 500 票/日 |

加工封顶（成品回收价 ≤ 材料回收价合计的 2 倍）只管「单次不能无中生有」，
没管「每天能做多少次」。灶台日产出仍是种地的 5 倍左右。
要改需要定产能上限或每次做饭的耗时/耗能，属于玩法决定，这次不改。

## 2. 小号水龙头（给新号发钱的口子）

| 来源 | 现状 |
| --- | --- |
| 基金补贴 | 每个新号至多托到 800 票；**从基金池里发，不是凭空造票**（池空为止），但小号会和真人分这个池 |
| 联盟周奖励 | 每个捐过 1 件的人 +25 票 |
| assist 互助 | 每对号每日 +8~10 票 |
| 钱庄借款 | 每号 ≤ 400 票 |

其中联盟周奖励（+25）和 assist（+8/+10）是系统直接造票，基金补贴和钱庄借款不是（前者是池子再分配，后者要还）。单个口子都不大，但可以按小号数量线性放大。需要统一的「单人/单设备/单邀请关系」限额。这次不碰。

## 3. 统一定价自己留下的两个口子

- **Tt 退货的跨号漏洞**：退货价 = 玩家此刻买入价 × 0.9，按「同一玩家同一时刻」恒亏一成。
  但高好感号（买入价 0.75×标价）把货送给 0 心小号，小号按 0 心价退 0.9×标价，净赚约 15%。
  建议修法：退货价再封顶为 `floor(0.9 × ceil(0.75 × 标价))`。需要玩法决定，未改。
- **栗栗劳动货换家具溢价**：劳动产出的货（非系统可买品）在栗栗换家具时，比去棚屋折旧回收略高，
  是小额溢价，不构成循环，记在这里备查。
